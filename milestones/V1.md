# V1 — Developer preview
- Sequence: 3
- Title: Developer preview
- Baseline: §61
- Hardware scope: H-001, H-002, H-004
- Surfaces to freeze: S-014, S-031
- Risks to retire: R-005, R-012, R-025, R-026, R-027, R-028, R-029, R-030, R-031, R-032, R-033, R-034, R-069, R-077, R-079, R-080, R-083

## Purpose

Make the OS useful enough that its developers build the OS while running the OS. A stable native SDK v1, self-hosted toolchain, networking, audio, GPU acceleration, power management and Linux compatibility good enough for daily development. Layer 2 interface-evolution rules (S-014) and the SDK v1 crate API (S-031) are freeze candidates: named here so the V1 SDK compatibility suite has a surface, frozen later per I-040 for Layer 1 and at V4 for remaining Layer 2 versions. Wine bring-up, the Wine test suite (C-011) and W1 harness definition run as non-gated work so V2 is not a research programme.

## Not in this milestone

Windows personality as a gate (feasibility spike and C-011 publish only). HDR, VRR, multi-GPU, fractional scaling. Bluetooth as a gate. End-user installer (developers install from a scripted image). Native app store UI. Native browser or IDE. Full-disk encryption UI (encryption may be configured manually). Permissions UI beyond a log viewer. Assistive-technology client. Localization beyond English. Any Layer 1 freeze.

## Gates

### V1-G01 · Self-hosted image builds bit-for-bit
- Kind: functional
- Verified by: BLD-049, ENV-020, BLD-043, BLD-041
A clean checkout builds the full system image on the OS inside an `os env` environment. The produced image boots and passes the V0 and V0.5 acceptance suites. Reproducibility of the image is verified bit-for-bit across two machines.

### V1-G02 · Core team daily-drives the OS
- Kind: functional
- Verified by: HW-015, APP-010, APP-016, APP-011, GOV-032
Every core team member has used the OS as their primary development machine for the working-day count named in the verifying task, with issues tracked. No open P0 issues that force a fallback to another OS.

### V1-G03 · SDK v1 published with a compatibility suite
- Kind: functional
- Verified by: SDK-059, SDK-036, BLD-037, SDK-057
SDK v1 is published with a semver policy. The SDK compatibility test suite passes for applications built against the v1.0.0 crate after each subsequent v1.x release during the milestone. S-031 is the freeze candidate this suite tracks.

### V1-G04 · Cached os env enter presents a working shell
- Kind: functional
- Verified by: SDK-041, ENV-018, ENV-014
`os env enter` on a cached environment presents a working shell with declared services reachable. Latency is gated by B-025, not here.

### V1-G05 · Wi-Fi connects, roams and survives suspend
- Kind: functional
- Verified by: NET-020, NET-021, NET-012, NET-003
Wi-Fi with WPA2 and WPA3 connects, roams between two access points and survives suspend/resume on H-004. DHCP and DNS work. A component without a network capability cannot open a connection.

### V1-G06 · Native audio and PipeWire compatibility coexist
- Kind: functional
- Verified by: AUD-010, AUD-001, AUD-014
Audio plays through the native path and through PipeWire compatibility simultaneously without glitches over the duration named in the verifying task. Round-trip is gated by B-028.

### V1-G07 · Suspend and resume succeed on laptop and desktop
- Kind: functional
- Verified by: PWR-014, LAB-009, AUD-012
Suspend/resume succeeds for the automated cycle counts named in the verifying task on H-004 and H-002, with Wi-Fi, display and audio functional afterwards.

### V1-G08 · GPU-accelerated Linux applications run
- Kind: functional
- Verified by: LNX-031, GFX-057, LNX-061, LNX-049, LNX-055, LNX-021
A browser with WebGL, an OpenGL sample and a Vulkan sample run through the Linux personality with acceleration confirmed via frame-rate comparison to software rendering. Seccomp-bpf, user namespaces, overlayfs, ptrace-equivalent and file-watch Operations are present so Chromium, Flatpak, podman and IDEs can run.

### V1-G09 · Signed repository rejects a tampered package
- Kind: functional
- Verified by: PKG-055, REL-007, PKG-062, PKG-066
Packages are content-addressed, signed and verified before activation. A tampered package is rejected. An update delivered from the repository creates a new generation. Running applications whose package is replaced do not observe a mixed-version tree.

### V1-G10 · Native debugger attaches to an async task
- Kind: functional
- Verified by: SDK-038, SDK-051, OBS-041, SDK-046
A native debugger attaches to a component, breaks at a source line inside an async task and shows the logical task stack. `os trace` exports a session that can be viewed offline. A native profiler attributes samples to Task and Component.

### V1-G11 · os restore returns to a previous generation
- Kind: functional
- Verified by: PKG-060, SDK-044
`os restore` to a previous generation restores kernel, packages and system configuration, verified in CI after a simulated bad update.

### V1-G12 · Semantic interfaces and a Wasm channel prototype
- Kind: functional
- Verified by: SEM-008, APP-015, WASM-012, WASM-013, DOC-010
An automation script invokes Terminal.run and Editor.open through typed interfaces without GUI input, recorded as a permanent test. A Wasm component exchanges typed messages over a native `Channel<T>` with a machine-code component. IDL-to-docs generation exists so later rungs are not writing reference pages by hand.

### V1-G13 · Kernel fork tracks one upstream stable release
- Kind: functional
- Verified by: KRN-040
At least one upstream stable release has been rebased or adapted during V1 following the divergence policy, with C-001 still green.

### V1-G14 · Prior benchmarks show no unexplained regression

Satisfied when the B-004 target for V1 is met on H-002. B-005 and B-001 V1 absolute targets are published in the same session beside Linux UDS, futex, fork+exec, clone and podman run.

### V1-G16 · Cached environment startup meets the V1 absolute target
- Kind: benchmark
- Verified by: BEN-025, ENV-014, BEN-030
- Benchmark: B-025
Satisfied when the B-025 target for V1 is met on H-002. Cold startup is published. B-016 for Terminal and Editor is published in the same session.

### V1-G17 · Idle power and battery runtime published
- Kind: benchmark
- Verified by: PWR-006, BEN-024, AUD-004, LNX-026, BEN-027, BEN-023

Satisfied when the B-031 target for V1 is met on H-004 beside a mainline Linux distribution on the same machine. No superiority claim. Audio round-trip (B-028), Linux compatibility overhead (B-026) and full-image build time (B-039) are published in the same session.

### V1-G18 · L0 corpus still has zero regressions
- Kind: compatibility
- Verified by: LNX-041, KRN-040, LNX-037

### V1-G19 · L2 corpus meets its threshold
- Kind: compatibility
- Verified by: LNX-056, LNX-038, UIP-042, LNX-041
- Corpus: C-003
Satisfied when the C-003 threshold for V1 is met on H-002 and H-004. C-002 remains at zero regressions. Integration scoring (launcher, task switcher, clipboard, portal file chooser, notifications, scaling) is part of each L2 GUI scenario.

### V1-G20 · V1 decisions, freeze candidates and roll-up
- Kind: process
- Verified by: GOV-038, SDK-054, SDK-055, NET-006, AUD-002, REL-003, LNX-018, WASM-007, SDK-028, LNX-015, KRN-024, KRN-026, SEC-029, IPC-046, SDK-057, WIN-016, WIN-017, WIN-009, WIN-006, NET-017, ENV-021, MED-010, GOV-037
Accepted decisions exist for SDK stability policy, network capability model, audio object model, package signing and trust roots, Linux personality D-Bus and portal strategy, Wasm role, `std` at Layer 3 only, ia32 retention, eBPF native role, kernel live-patching as a non-goal, and the microarchitectural side-channel position statement. S-014 and S-031 are freeze candidates; Layer 1 surfaces remain unfrozen. C-011 is published with a feasibility report and no pass-rate gate. W1 corpus definition and per-title harness exist. Remote shell via the Linux personality is available with listen capability explicit. Every V1 task is `done` or `dropped` with reason and the generated roll-up is complete.

## Notes

Wine-on-LNX bring-up and C-011 are deliberately non-gated. JakeOS guest images (VIRT) may ship so developers can onboard in a VM; they are not a gate. Display power management is in scope on H-004. The system CA trust store is a typed object consumed by native TLS and mirrored into the personalities.
