# V2 — Desktop preview
- Sequence: 4
- Title: Desktop preview
- Baseline: §62
- Hardware scope: H-001, H-002, H-004, H-005
- Surfaces to freeze: S-019
- Risks to retire: R-035, R-036, R-037, R-038, R-039, R-040, R-041, R-042, R-043, R-044, R-045, R-068, R-070, R-078, R-084

## Purpose

Deliver a polished desktop with laptops, multi-monitor, HDR, VRR, Bluetooth, Windows applications and a gaming proof-of-concept, rollback and snapshots, a native repository, and semantic automation, on three deliberately constrained target machines. The component manifest (S-019) freezes; the UI protocol (S-015) and package manifest (S-018) are freeze candidates whose Layer 2 lock happens at V4. Semantic registry, then automation rules, then the AI-broker demo, in that order. NVIDIA (H-006) is tracked as experimental with no gate.

## Not in this milestone

Installer for the general public (still image-based install with a guided script). Crash reporting pipeline and hardware compatibility database as products. Public package submission process. Kernel-level anti-cheat games. NVIDIA as a gated target. Distributed or remote interfaces. Native filesystem. Certification of accessibility compliance. Any Layer 1 freeze.

## Gates

### V2-G01 · Desktop shell passes the UX script on all three machines
- Kind: functional
- Verified by: APP-048, BLD-056, UIP-051, SCH-051
The desktop shell passes the forty-scenario desktop UX script (launch, switch, notify, settings, lock, unlock, external display, scaling change) on H-002, H-004 and H-005 with zero P0 or P1 defects.

### V2-G02 · Multi-monitor hot-plug does not lose windows
- Kind: functional
- Verified by: GFX-077, GFX-071, GFX-075, UIP-047
Two displays with different scale factors and refresh rates, hot-plug and unplug the count named in the verifying task without compositor restart or window loss. DisplayPort MST and daisy-chained docks are included in the test.

### V2-G03 · HDR10 and VRR verified on the reference display
- Kind: functional
- Verified by: GFX-068, GFX-088, WIN-032, GFX-067, GFX-079
HDR10 output verified on the HDR display attached to H-002 with a native HDR test application and a Windows-personality HDR game. VRR verified via display reporting at variable frame rates. Hardware cursor, overlay planes and direct scanout are in place for fullscreen games and HDR video.

### V2-G04 · Bluetooth pairing and reconnect meet the cycle threshold
- Kind: functional
- Verified by: HW-060, HW-037, HW-038, SVC-034
Pairing and reconnect of a headset (A2DP and HFP), a mouse and a keyboard succeed for the automated pairing cycles named in the verifying task. A user-space Bluetooth stack crash is recovered without reboot.

### V2-G05 · Laptop suspend soak and battery estimate
- Kind: functional
- Verified by: PWR-024, LAB-014, PWR-023, SEC-048
Automated suspend/resume cycles per laptop (H-004, H-005) meet the success rate named in the verifying task with full function after. Battery estimate is within the tolerance named in the verifying task of measured runtime.

### V2-G06 · Windows application launches as a native citizen
- Kind: functional
- Verified by: WIN-027, WIN-024, WIN-020, WIN-021, WIN-042, WIN-044
A Windows application launches by double-clicking an `.exe`, appears in taskbar and launcher, uses the native file chooser and clipboard, with no separate desktop or wizard. Runtime redistributables are packaged as prefix dependencies. Personality version pinning is surfaced in native UI.

### V2-G07 · Gaming proof of concept on W1 Gold titles
- Kind: functional
- Verified by: WIN-029
At least the W1 Gold-with-HDR-or-VRR count named in C-007's V2 threshold runs with GPU acceleration, HDR or VRR where supported, and gamepad input. FPS is gated by B-027, not here.

### V2-G08 · Snapshots, rollback UI and automatic rollback
- Kind: functional
- Verified by: INS-014, PKG-077, BOOT-028, PKG-073, CAP-043
Snapshots and rollback are in the settings UI. A user can restore a previous generation and a previous package set from the UI. A fault-injected broken update automatically boots the previous generation, tested on H-002, H-004 and H-005. Persistent grants survive application updates and revoke on publisher change.

### V2-G09 · Native repository with capability review at install
- Kind: functional
- Verified by: APP-045, SEC-038, SEC-047, CMP-043, PKG-075, WASM-016
Install, update and remove from the store client. Capability requests are shown and can be denied at install, with the application still launching in a degraded mode where it declares optional capabilities.

### V2-G10 · Permissions UI lists and revokes every grant
- Kind: functional
- Verified by: SEC-045, APP-029, SEC-036, CAP-044
The permissions UI lists every active grant for every application and revocation takes effect immediately, tested with camera, microphone, files, network and screen capture.

### V2-G11 · Screen sharing is an explicit capability with an indicator
- Kind: functional
- Verified by: SEC-046, GFX-061, GFX-082, APP-031, APP-038
An application without the screen-capture capability receives a black or denied surface. Sharing shows a persistent indicator.

### V2-G12 · Semantic automation and an AI-assistant demo
- Kind: functional
- Verified by: SEM-019, SEM-020, SEM-021, SEM-010, SEM-009, SEM-029, SEC-033
Three shipped example rules (download completed then extract; meeting start then create note; project opened then start environment) run without GUI input. ### V2-G13 · Screen-reader prototype completes the four-app script

- Verified by: ACC-021, ACC-017
