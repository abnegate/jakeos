# V0 — Execution model
- Sequence: 1
- Title: Execution model
- Baseline: §59
- Hardware scope: H-001, H-002
- Surfaces to freeze: none
- Risks to retire: R-001, R-002, R-003, R-004, R-006, R-007, R-008, R-009, R-010, R-011, R-013, R-014, R-067, R-073, R-074, R-075

## Purpose

Prove that the native execution model exists inside a booting Linux fork without breaking Linux hardware support. Components, tasks, capabilities, typed channels, async operations, MemoryObjects, ResourceDomains and tracing run on QEMU and one AMD reference desktop. Native components start from a retained initramfs; a native init is not a V0 deliverable. Every Layer 1 surface is prototyped. Every V0 benchmark is publish-only. The threat model is published. A Windows-personality scoping decision is the only WIN deliverable.

## Not in this milestone

Compositor, UI protocol and graphics abstractions. Packages, system generations and storage beyond raw block and filesystem passthrough. Native filesystem or content-addressed store. Windows personality implementation. Wasm beyond a decision. Heterogeneous compute beyond a ComputeDevice enumeration decision. Installer, updater, security UI and disk encryption. Any hardware other than H-001 and H-002. Performance tuning beyond measuring and publishing. Native init. Any Layer 1 freeze.

## Gates

### V0-G01 · Fork boots on QEMU and the reference desktop
- Kind: functional
- Verified by: BOOT-001, BOOT-002, BOOT-005, KRN-019
A CI-built image boots the kernel fork on H-001 and H-002 from a retained initramfs and starts native components beside it. Boot is reproducible from a tagged commit.

### V0-G02 · Component create, run and destroy reclaims resources
- Kind: functional
- Verified by: CMP-005, CMP-004, CAP-006
A native Component is created, given capabilities, runs code and is destroyed with all resources reclaimed. A leak test that creates and destroys components at the scale recorded in the verifying task shows no unbounded kernel-memory growth.

### V0-G03 · Capability derivation attenuates and forgery fails
- Kind: functional
- Verified by: CAP-003, CAP-011
`Capability<File, ReadWrite>` derives `Capability<File, Read>`. An attempt to derive Admin or to forge a handle returns `Error::Rights` and allocates no handle.

### V0-G04 · Revocation invalidates derived capabilities
- Kind: functional
- Verified by: CAP-004
Revoking a capability makes every derived capability fail within one operation, including a derivation tree of the depth recorded in the verifying task.

### V0-G05 · Channel carries typed messages and Layer 1 negotiation
- Kind: functional
- Verified by: IPC-010, IPC-012, IPC-021, ABI-004
`Channel<T>` carries typed messages generated from the IDL. A message with an unknown newer field is accepted by an older receiver and an older message by a newer receiver. The Layer 1 version-negotiation handshake (S-011) is tested at kernel entry, not only as an IDL message test.

### V0-G06 · MemoryObject ownership transfer copies no payload
- Kind: functional
- Verified by: MEM-010, MEM-012, IPC-014
A MemoryObject capability is transferred between two components without copying the payload, verified by physical-page identity.

### V0-G07 · Operations submit, complete, time out and cancel
- Kind: functional
- Verified by: TSK-024, TSK-010, TSK-011, TSK-012
Async Operation submission and completion work for Read, Write, Send, Receive, Timer and Wait. An operation with a deadline completes with a Timeout result. A cancelled operation never delivers a result.

### V0-G08 · TaskGroup cancellation is bounded
- Kind: functional
- Verified by: TSK-023, TSK-022
Cancelling a TaskGroup cancels every owned task and child group within the bound recorded in the verifying task, including a multi-level tree.

### V0-G09 · ResourceDomain enforces memory budget and CPU share
- Kind: functional
- Verified by: SCH-008, SCH-006, SCH-009
A component in a ResourceDomain cannot exceed its memory budget. A CPU share is enforced within the tolerance recorded in the verifying task under contention. Kernel-object consumption is bounded with typed exhaustion errors.

### V0-G10 · os inspect and os trace cover every live primitive
- Kind: functional
- Verified by: SDK-007, SDK-008, OBS-007, OBS-005, OBS-009, CAP-002
`os inspect` prints state, ownership and relationships for component, task, channel, capability, memory and resource. `os trace` shows IPC flow and scheduling delays for the demo.

### V0-G20 · V0 decisions, Rust policy, threat model and roll-up
- Kind: process
- Verified by: CAP-008, ABI-010, CAP-010, IPC-006, IPC-003, CMP-010, WIN-001, BOOT-004, GOV-007, ABI-020, ABI-021, LAB-004, SDK-010
Every V0 architecture decision (handle representation, capability encoding, IDL, fast-path mechanism, wrapper-versus-native for components, Windows scoping, V0 boot strategy) has an accepted decision listing at least two options. The threat model enumerates T-001 through T-042. All new kernel and runtime code is Rust unless a decision exempts a specific file; clippy and rustfmt are clean in CI. Every V0 task is `done` or `dropped` with a written reason and the generated roll-up is complete. Layer 1 surfaces S-001 through S-012 are `prototyped` or still `open` with a spike in flight; none are `frozen`.

## Demos

### V0-D01 · Component to Channel to MemoryObject round trip
- Verified by: CMP-011, MEM-012, SDK-002
Native Component A sends `Channel<Request>`. Component B decodes, allocates a MemoryObject, transfers ownership back. A reads the result without a copy. Shown live with `os trace` displaying the flow on H-002.

### V0-D02 · TaskGroup cancellation tears down the pipeline
- Verified by: TSK-022, CMP-004
Killing the parent TaskGroup tears down A, B and all in-flight operations deterministically.

### V0-D03 · Component panic yields a typed disconnect
- Verified by: CMP-011, IPC-011
B panics. A observes a typed disconnect and rebinds to a restarted B. The panic does not unwind across the ABI.

### V0-D04 · Isolation denial is a typed error in the audit log
- Verified by: CMP-012, CAP-001, SEC-001
B attempts to open a file it has no capability for and receives a typed denial visible in the audit log.

### V0-D05 · Linux busybox and L0 run beside native components
- Verified by: BOOT-005, LNX-001, LNX-002
A busybox shell and the C-001 corpus run side by side with native components on the same kernel on H-002.

## Notes

V0 hardware is H-001 and H-002 only. An Intel laptop may be procured under R-022 but nothing gates on it. Wine, compositor and packages are out. B-001's V0 advisory band and the Or decision are defined in the register, not here. Q-001 must close before published numbers are comparable across machines.
